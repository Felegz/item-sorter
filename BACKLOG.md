# Backlog

## Альтернативы отображения дат

Сейчас выбран `date-fns 4.4.0`: календарные формулировки в русской локали,
включая «в прошлую пятницу», объединяются с компактными абсолютными датами.

Если формат захочется переделать, отдельно рассмотреть:

- `Luxon DateTime.toRelativeCalendar()` — проще единый объект даты и часового
  пояса, но нет нужного акцента на днях недели.
- Нативный `Intl.RelativeTimeFormat` без внешней библиотеки — самый лёгкий
  вариант для «сегодня», «послезавтра», «через 3 дня», но не умеет
  «в прошлую пятницу».
- `Day.js` с плагином `Calendar` — небольшой модульный вариант, но требует
  отдельного плагина и русской локали, не давая проекту заметного преимущества.
- Полностью числовой режим `formatDistanceToNowStrict()` — «через 3 дня»,
  «5 дней назад» для всех близких дат. Быстро читается как интервал, но хуже
  связывает задачу с календарной неделей.
- Двойная подпись — «в среду · через 3 дня». Информативнее, но плотнее и может
  создавать шум в большом списке.

Перед сменой формата сравнить варианты на реальном списке отдельно для срока
`due:`, даты создания и статуса синхронизации: у этих дат разный смысл.

## Единая политика приоритетов при перемещении задач

Сейчас разные операции могут сохранять, переназначать или оставлять разрывы в
todo.txt-приоритетах `(A)`, `(B)` и далее. Не исправлять это попутно внутри
фильтрации, сортировки или миграции секций.

Отдельной задачей:

- перечислить все функции, которые перемещают задачи между списками;
- определить единое правило для сохранения, удаления и перенумерации
  приоритетов;
- отдельно решить поведение для `sorted`, `partiallySorted`, inbox и ignored;
- закрепить правило общим переиспользуемым преобразованием и тестами;
- только после этого подключать его к функциям по одной.

## Несколько независимых ignored-блоков

Текущий контракт временно допускает только один `IGNORED TASKS (дата)`. Если
операция встречает несколько таких блоков, она должна остановиться без записи,
а не объединять их.

Для будущей реализации нужна модель `ignoredSections`, где каждый блок хранит
свой маркер, дату и задачи. Новые ignored-задачи должны добавляться в начало
первого блока, а остальные блоки должны сохраняться отдельно и без изменений.
