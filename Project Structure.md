# Sorter-Помогатор — описание проекта

> Этот файл создан для быстрой ориентации в проекте. Он описывает структуру файлов, логику работы и все режимы приложения.

---

## Что это за проект

Веб-приложение для управления задачами по методологии GTD (Getting Things Done). Состоит из двух частей:

1. **sorter 2025** — основное рабочее приложение (HTML + Vanilla JS, без фреймворков).
2. **Twine Pomogator** — прототип алгоритма GTD-разбора, написанный в Twine (интерактивная художественная программа). Является прадедом логики `process.html`.

Деплой: `https://item-sorter.pages.dev/` (Cloudflare Pages).

## Страницы и их роль

### `index.html` + `app.js` — Главный редактор

Основной экран. Большой `<textarea>` для списка задач в формате todo.txt. Все задачи хранятся в `localStorage`.

**Группа «Задача»:**
| Кнопка | Функция |
|---|---|
| ✅ Отметить выполненной | `toggleDoneCurrentLine()` — ставит/снимает `x DATE` на текущей строке курсора |
| 🏆 Присвоить приоритеты | `assignPrioritiesAfterSort()` — расставляет `(A)(B)(C)…` сверху вниз |
| ⚙ Обработать (GTD) | Открывает `process.html?task=…` с текущей строкой |
| ⚡ Быстрый разбор | `quickTriageCurrentTask()` — упрощённый КОРЗИНА-флоу прямо на странице через SweetAlert2 |

**Группа «Сортировка»:**
| Кнопка | Функция |
|---|---|
| Filter Tasks | `filterTasksUI()` — для каждой задачи показывает диалог: Включить / Игнорировать / Удалить |
| Sort Tasks | `sortTasks()` — сортирует задачи по важности через серию парных сравнений |
| Insert Unsorted Tasks | Вставляет новые задачи в уже отсортированный список (бинарная вставка) |
| Merge Arrays | `mergeArraysUI()` — сливает два блока (разделённых маркером `NEW ARRAY`) |

**Группа «Данные»:**
| Кнопка | Функция |
|---|---|
| Copy | Копирует задачи в буфер (без пустых строк) |
| Save .txt | Скачивает файл `tasks_ДАТА_ПЕРВАЯ-ЗАДАЧА.txt` |
| Войти в Dropbox | OAuth PKCE авторизация |
| В Dropbox / Из Dropbox | Сохранить/загрузить `/tasks.txt` в Dropbox |

### `process.html` — GTD-Помогатор

Открывается с параметром `?task=...` (URL-encoded текст задачи). Реализует два флоу:

#### Флоу «📥 Разбор корзины» (`korz`)

```
С этим надо что-то делать?
├── НЕТ → Мусор / Когда-нибудь / Справочная информация
└── ДА
    └── Мне? 
        ├── НЕТ → Делегировать (кому? → @имя в теге)
        └── ДА
            └── Сейчас / на этой неделе?
                ├── Конкретная дата → В календарь (due:ДАТА)
                ├── Когда-нибудь потом → someday
                └── ДА
                    └── Задача мутная?
                        ├── ДА → переключиться на флоу «mutny»
                        └── НЕТ
                            └── < 2 минут?
                                ├── ДА → Сделать сейчас
                                └── НЕТ → Следующее действие (next_action)
```

#### Флоу «🔮 Мутная задача» (`mutny`)

```
1. Какой результат должен быть? [textarea]
2. Запиши ОДНО следующее действие [textarea]
3. Есть глагол-прокрастиноген? (подумать / изучить / сделать…)
   ├── ДА → Переписать → вернуться к п.2
   └── НЕТ
       └── Приоритет? (🔴 Срочно / 🟢 Обычный)
           └── Контексты? (@дом / @работа / @компьютер…)
               └── → Вывод готовой строки todo.txt
```

**Результат** (`action` типы):
- `trash` — удалить
- `someday` — добавить тег `someday:yes`
- `ref` — добавить тег `ref:yes`
- `delegate` — добавить тег `@имя`
- `calendar` — добавить `due:ДАТА`
- `now` — пометить выполненным `x DATE`
- `next_action` — сформировать строку todo.txt и предложить скопировать или добавить в список

### `tasks.html` — Таск-трекер

Визуальный список всех задач из того же `localStorage`. Читает задачи в формате todo.txt.

**Возможности:**
- Быстрое добавление задачи (строка ввода вверху)
- Поиск по тексту
- Фильтрация по вкладкам: Все / Активные / Выполненные
- Фильтрация чипами по приоритету `(A–D)`, проектам `+proj`, контекстам `@ctx`
- Сортировка по приоритету / дате создания / дате due
- Новая задача всегда получает дату создания и попадает в начало `inboxUnsorted`
- Команда «Отсортировать» на строке бинарно помещает одну задачу в `sorted`
- Отметить задачу выполненной чекбоксом
- Кнопка GTD-разбора на каждой строке (открывает `process.html`)
- Секция «игнорируемых задач» (свёрнута, отображается пунктиром)

## Формат данных — todo.txt

Задачи хранятся в `localStorage` под ключом `tasks` в формате [todo.txt](https://github.com/todotxt/todo.txt):

```
(A) 2026-04-01 Позвонить клиенту @телефон +проект due:2026-04-20
x 2026-04-15 2026-04-10 Сдать отчёт +работа
```

### Расширенные поля GTD-разбора

`task-format.js` читает и записывает поля в фиксированном порядке:

```text
(A) 2026-09-06 Следующее действие @дома #важно due:2026-09-09 ➤цель:Нужный результат ➤сложность:Что мешает ➤совет:Что поможет ➤исходное:Текст до разбора
```

- Канонические маркеры: `➤цель:`, `➤сложность:`, `➤совет:`, `➤исходное:`.
- Старый вид `⟦исх.: …⟧` по-прежнему читается, но при следующем
  редактировании задача записывается в каноническом виде.
- Загрузка списка сама по себе не переписывает старые строки.
- Видимый HTML на `/tasks` и в фильтрах главной страницы строится через
  `TaskFormat`. Диалог попарной сортировки временно восстановлен дословно из
  рабочего коммита и пока показывает сырой текст задачи.
- Даты форматирует `date-fns 4.4.0` с русской локалью; точная календарная дата
  остаётся в `title`. Альтернативы зафиксированы в `BACKLOG.md`.

**Более поздняя внутренняя модель списков:**

| Имя в коде | Маркер или положение в тексте | Смысл |
|---|---|---|
| `inboxUnsorted` | новые строки перед `SORTED` или после `НЕУПОРЯДОЧЕННЫЕ ЗАДАЧИ` | Новые задачи без установленного внутреннего порядка |
| `inboxSorted` | `NEW ARRAY` | Отдельная отсортированная партия из старого/manual сценария Merge Arrays; обычный Sort Tasks её не создаёт |
| `sorted` | `SORTED (ГГГГ.ММ.ДД)` | Основной список в установленном порядке приоритета |
| `partiallySorted` | `PARTIALLY SORTED (ГГГГ.ММ.ДД)` | Обработанный алгоритмом остаток без гарантии полного порядка |
| `ignored` | `ИГНОРИРУЕМЫЕ ЗАДАЧИ ГГГГ.ММ.ДД` | Намеренно исключённые задачи |

`parseTaskDocument()` используется более поздними операциями одной задачи. Он
понимает как текущую раскладку, где `inboxUnsorted` находится вверху до
`SORTED`, так и старую раскладку
`sorted / NEW ARRAY / inboxSorted / НЕУПОРЯДОЧЕННЫЕ ЗАДАЧИ / inboxUnsorted`.

Четыре восстановленные старые команды сортировки пока намеренно не используют
этот универсальный парсер. У `Sort Tasks` и `Merge Arrays` разные исторические
правила разрезания одного текста. Их точные контракты находятся в
[`docs/SORTING_BEHAVIOR_SOURCE_OF_TRUTH.md`](docs/SORTING_BEHAVIOR_SOURCE_OF_TRUTH.md).

`serializeTaskDocument()` собирает более позднюю модель в порядке:
`inboxUnsorted`, `SORTED`, `NEW ARRAY`, `PARTIALLY SORTED`,
`ИГНОРИРУЕМЫЕ ЗАДАЧИ`. Восстановленные старые команды пока используют свои
исходные способы сборки; переводить их на этот сериализатор можно только по
одной с characterization-тестом.

## Алгоритмы сортировки

Сортировка основана на **попарных сравнениях задач пользователем**. Функция `compareTasks(task1, task2)` показывает диалог SweetAlert2 с двумя кнопками и возвращает Promise с `-1` (task1 важнее) или `1` (task2 важнее).

Полное и обязательное описание находится в
[`docs/SORTING_BEHAVIOR_SOURCE_OF_TRUTH.md`](docs/SORTING_BEHAVIOR_SOURCE_OF_TRUTH.md).
Ниже приведена только краткая карта действующего восстановленного кода.

| Алгоритм | Где используется | Особенности |
|---|---|---|
| `mergeSort()` + `merge()` | Sort Tasks для новой партии до 60 задач | Полностью сортирует только новую партию |
| `partialSortTasks()` + `heapifyDown()` | Sort Tasks для партии больше 60 задач | Извлекает верхние 20%, максимум 50; возвращает heap-остаток |
| `promoteTailCandidates()` | Необязательная проверка в Sort Tasks | Проверяет хвост сверху и останавливается после первого проигрыша |
| `mergeGalloping()` + `gallopRight/Left()` | Старый Merge Arrays | Сливает два уже упорядоченных блока вокруг `NEW ARRAY` |
| встроенный бинарный поиск в `insertUnsortedTasksUI()` | Insert Unsorted Tasks | Вставляет задачи в общий блок выше игнорируемых задач |
| `findRankedInsertionIndex()` | Более поздняя сортировка одной задачи | Не относится к восстановленному пакетному Insert Unsorted Tasks |

### Контракт кнопок сортировки

- `Sort Tasks` сортирует только задачи выше `SORTED`. Новую отсортированную
  партию целиком ставит перед прежним `SORTED`, не смешивая два блока
  дополнительными сравнениями.
- При партии больше 60 задач верхние 20%, но не более 50, попадают в новый
  `SORTED`; heap-остаток добавляется перед прежним `PARTIALLY SORTED`.
- Проверка `PARTIALLY SORTED` идёт сверху вниз и завершается после первого
  кандидата, который не оказался важнее конца `SORTED`.
- `Sort Tasks` не поглощает `NEW ARRAY`. Этот маркер принадлежит отдельному
  сценарию `Merge Arrays`.
- `Merge Arrays` сливает задачи до и после `NEW ARRAY`, а затем оставляет в
  результате пустой маркер `NEW ARRAY` и исходный хвост от
  `НЕУПОРЯДОЧЕННЫЕ ЗАДАЧИ`.
- `Insert Unsorted Tasks` исторически считает единым упорядоченным массивом все
  немаркерные строки выше `ИГНОРИРУЕМЫЕ ЗАДАЧИ`.
- `Filter Tasks` собирает активные строки всего документа, удаляет точные
  дубликаты и полностью пересобирает список как включённые и игнорируемые.
- Старый код может терять выполненные строки вне ignored-tail. Это зафиксированная
  опасная особенность эталона, а не желаемое улучшение; исправлять её нужно
  отдельно и явно.

### Канонические операции одной задачи

`task-list-operations.js` — источник истины для более поздних действий, которые
меняют положение одной конкретной задачи. Экран `/tasks` использует
`findRankedInsertionIndex()`. Восстановленная пакетная вставка главной страницы
пока использует собственный исторический бинарный поиск.

- `prepareNewTask(raw, options)` разбирает строку через `TaskFormat`, добавляет
  отсутствующую дату создания в позицию todo.txt и хранит срок отдельно как
  `due:ГГГГ-ММ-ДД`.
- `insertTaskIntoInbox(document, raw, options)` ставит задачу первой строкой.
  Если `SORTED (…)` отсутствует, функция создаёт этот маркер сразу после новой
  задачи; прежний документ остаётся ниже границы inbox.
- `findRankedInsertionIndex(ordered, candidate, compare)` выполняет бинарный
  поиск по списку «важнее → менее важно». Контракт comparator: отрицательное
  число означает, что кандидат должен быть выше текущей задачи; положительное —
  ниже. Требуется не более `ceil(log2(n + 1))` сравнений.
- `rankTaskAtIndex(document, sourceIndex, compare)` удаляет конкретное вхождение
  строки по индексу и только после завершения сравнений вставляет его в блок
  `sorted`. Поэтому одинаковый текст задач не путается, а отменённый диалог не
  изменяет документ.

## Подсветка и фильтр-бар (`todotxt.js`)

- Поверх `<textarea>` рендерится прозрачный HTML-слой с подсветкой (`hl-layer`)
- Подсвечиваются: приоритеты `(A–Z)`, теги `key:value`, проекты `+proj`, контексты `@ctx`, даты, просроченные `due:`
- Фильтр-бар над полем автоматически собирает все проекты, контексты, приоритеты из текста и рендерит чипы-фильтры

## Twine Pomogator (архив/прототип)

Папка `Twine Pomogator/` содержит первоначальный прототип GTD-алгоритма, написанный в Twine на языке Harlowe. Он реализует ту же логику разбора корзины, что сейчас живёт в `process.html`. Файл `algorithm.md` — текстовая блок-схема того же алгоритма, использовалась при проектировании `process.html`.
